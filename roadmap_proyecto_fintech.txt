FASE 3: DATA WAREHOUSE Y TRANSFORMACIONES DBT (ANALYTICS ENGINEERING FOCUS)
-------------------------------------------------------------------------------
[ ] 3.1. Inicialización de dbt
    - Configurar dbt-postgres o dbt-duckdb dentro de dbt_fintech/.
    - Configurar profiles.yml para conectarse a la base OLAP / Lakehouse.

[ ] 3.2. Capa Bronze / Staging (dbt)
    - Crear stg_transactions.sql: Limpieza de tipos de datos, casteo de timestamps y renombrado.
    - Crear stg_users.sql: Estandarización de datos de clientes.

[ ] 3.3. Capa Silver / Intermediate (SCD Type 2 & Reglas de Negocio)
    - Configurar `dbt snapshot` sobre usuarios para registrar cambios en Scoring Crediticio a lo largo del tiempo.
    - Crear int_user_transaction_velocity.sql: Métricas en ventanas de tiempo (5, 15 y 60 min por usuario).

[ ] 3.4. Capa Gold / Marts (Modelado Dimensional Kimball)
    - Crear dim_users.sql: Dimensión de usuarios con estado actual e historial de scoring.
    - Crear fct_transactions.sql: Tabla de hechos transaccionales unificada.
    - Crear fct_fraud_alerts.sql: Tabla agregada con banderas de posibles fraudes según reglas.

[ ] 3.5. Testing y Calidad de Datos
    - Implementar tests primarios en schema.yml (unique, not_null, relationships).
    - Implementar tests con dbt-expectations (ej. expect_column_values_to_be_between para scoring 300-850).
